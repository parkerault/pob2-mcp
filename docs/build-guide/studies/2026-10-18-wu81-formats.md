# WU-81's formats, for WU-82 (M-18)

The run-folder formats that WU-81's scripts (`run-log.mjs`, `check-run.mjs`, `render-audit.mjs`) parse and check,
from the WU-81 doer's report (2026-10-18), as merged. WU-82 writes the skill text to match these exactly. Amendment 7
(`../spec/amendment-7-gate-interviews.md`) is the rule; this file is the shape.

## The card's Pitch

- **Layout.** The H1 is `# Card <id>: <Name>`. Each field is a top-level item `- <Field>: <text>` under `### Pitch`.
  Indented continuation lines and nested `  - ` items are joined with "; ".
- **Fields:**
  - `- Name:` 2–4 words. An old `Title:` is read as the name when there is no Name.
  - `- Why pick it:` at most two sentences.
  - `- How it clears:`
  - `- Bosses:` one sentence.
  - `- Needs:` key items, gems and passives; when it comes online; any respec; a rough cost.
  - `- The catch:` one sentence.
  - `- Under-played (judgment):` <why>. Only on an under-played card. The display shows it as "Unusual: <why>".
  - `- Not confirmed:` <the load-bearing link>: <what it would change>. Only when that link isn't confirmed in game
    text.
  - `- Playstyle:` tags. Kept on the card, never displayed.
  - `- Changed at the gate (visit <n>):` <the user's words>. R1b writes it on a card revised at a gate.
  - `- Made at the gate (visit <n>):` from <name> and <name>: <the user's words>. R1b writes it on a gate-made card.
- **The display** prints each card as `<k>. <Name>`, then the five pitch lines in order, then Unusual, Not
  confirmed, and the Made or Changed lines. It prints the "Not confirmed in game" default once itself; `cards.md`
  doesn't carry it.

## The deck, `cards.md`

**Its H2s, in this order:**
1. `What the cards share`: one paragraph, 1–80 words.
2. `How they differ`: exactly one line.
3. `Round 1` … `Round k`.
4. `Not dealt`: items, or `None.`
5. `Found, not used`: at most 5 items, `- <finding>: <why no card uses it>`, or `None.`

**Line formats:**
- **A dealt card:** `- <id> "<Name>" | <what it adds> [| under-played (judgment: <why>)] [| can't be finalized yet:
  <why>]`
- **A gate-made card,** added by R1b-assemble under round `k`:
  `- r<k>-g-<n> "<Name>" | <adds> | made at the gate (visit <n>): from "<Name>" and "<Name>"`
- **A not-dealt card:** `- <id> "<Name>" | <reason, in plain words>`

A gate-made card never appears under Not dealt, and never counts toward the 6–9 dealt cards or the under-played
count.

## Interview notes, `interviews/<gate>-<visit>.md`

- **Naming.** The gate is `brainstorm`, `verification`, `design`, `final` or `escalation`; the visit is the
  display's.
- **When.** The runner writes the file only when questions were asked.
- **Layout.** The H1 is free text (suggested: `# Questions at the <gate> gate, visit <v>`). Then, per question,
  numbered from 1:
  - `## Q<n>: <the user's question, trimmed>`
  - `Answer: <at most 3 lines, with its status words>`
  - `Source: <file | lookup call | interviews/<gate>-<v>-q<n>.md (a gate question step, <agent>)>`
- **The check.** The number of `Q` H2s equals the checkpoint's `questions`.

## A gate question step's report, `interviews/<gate>-<visit>-q<n>.md`

- **Naming.** `n` counts that visit's question steps from 1, one file per step. The visit's notes must cite it as a
  source.
- **Layout:**
  - `# Gate question <n>: the <gate> gate, visit <v>`
  - `- Asked: <the question or questions>`
  - `- Agent: build-guide-researcher | build-guide-coordinator`
  - `## Answer`
  - `## Sources`: one item per lookup, file or probe.

  Exactly these two H2s, `Answer` and `Sources`, and both list items are required.
- **A coordinator's variant** goes in `probes/q-<gate>-<visit>-<n>/`, measure-only.
- **The run log.** Each step is logged as `{"stage":"Q","attempt":1,"outcome":"done"}`.

## The checkpoint

`{checkpoint, visit, answer, answeredBy, rule?, questions?, changes?, newCards?, note?}`

- **`questions`:** a whole number ≥ 0, on the five displayed gates only, not the unsaved-build question. It is 0
  on a default answer and counts 0 when absent; the skill always writes it.
- **`changes`:** `{"<id>": "<words>"}`. Its keys are ids the answer names, on a brainstorm `pick:`, a verification
  `pick:` or a verification `verify:`. A brainstorm or `verify:` change needs the card's "Changed at the gate" line; a
  verification `pick:` change goes to D1-build as findings and needs none.
- **`newCards`:** `[{"id": "r<k>-g-<n>", "name", "from": [ids], "words"}]`, only with a brainstorm `pick:` or a
  verification `verify:`.
  - `k` is the latest brainstorm round; `n` is the next gate-made number in that round.
  - `from` may name any card `cards.md` lists, not-dealt cards included.
  - Picks plus new cards are at most 3. A pick of new cards only is written `pick:` or `verify:` with no id.
  - R1b runs the picked cards in order, then the new cards in order.
- **`note`:** only with `more`.
- **A pre-supplied object entry:** `rule` is its `answer` as written, and `questions` is its `ask` count.

## The test config

- **An entry** is a string, or `{ask?, answer, changes?, newCards?, note?}`.
- **`newCards` items** are `{name, from, words}`; the runner assigns the id.
- **`changes`, `newCards` and `note`** are allowed only on brainstorm and verification entries.
- **The check.** `run-log.mjs <runFolder> test-config <path>` checks a config. The rules that need the deck (a new
  card's `from`, a name no card already has) are checked when the checkpoint is written.
- **A refused entry.** When a checkpoint write refuses a pre-supplied entry on the deck rules, the run ends `stopped`
  with answer `stop`, `answeredBy: "default"`, and a rule that says why. The checker accepts that. WU-82 words the
  rule.
- **`offline-and-test.md`'s example** is run through `test-config` by a test, so it must stay well formed.
